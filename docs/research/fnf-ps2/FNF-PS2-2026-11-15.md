## Scope and measured structure

Retail PS2 uses ARCP, distinct from the Xbox prototype ARCX adapter. 7,747 outer files, 7,176 ARCP packages; 5,490 packages contain type9 static mesh descriptors. Counts describe inventory, not importer coverage.

ARCP: 128-byte header, countLE32 at4, 16-byte directory rows. Row idLE32,+4 offset relative to table end,+8 signed name offset,+12 type,+13 big-endian24 size. Type253 is the name pool; type255 labels packages. Type9 provides128-byte bounds; type7 identifies material states; type16 contains DMA/VIF geometry. Type2 materials and type1 PS2 GS textures require separate interpretation. No Xbox texture decoder or ordinal texture assignment applied.

## Track follow-up: packed and unlit layouts

The first car-only implementation omitted227/227 UCP000 packets. This is now superseded: src/fnf_ps2_packets.h admits both retail track layouts with complete per-resource checks.

- Mode1: V4-32 at VU0x8003 stores paired XZ (two vertices/vector), not paired XY. V4-32 at0x802f stores U,V,Y and a control/alpha word. Reconstruct source XYZ=(paired.x,attributes.z,paired.y). The first GIF tag is a triangle strip with ST/RGBA/XYZ2 registers; NLOOP is the actual vertex count, excluding one zero-alpha suppressed padding slot when the DMA count rounds up. Control word bit15 suppresses the draw kick. Exactly two suppressed vertices begin each admitted independent strip; no faces cross that boundary.
- Mode0: existing XYZ/UV/explicit-length profile can omit normal vectors. V4-8 at0xc035 contains colors rather than normals. Required color/UV/topology streams and lengths are checked; missing normals are generated from decoded faces. Existing lit car profile and counts remain supported.
- Original packed U/V/Y float bits are retained (the game also uses those floats in its transform); low bytes additionally carry RGBA. Source color attributes remain recorded in packetChunks; current MeshVertex cannot display their per-vertex color. No UV flip, ordinal texture selection or original shader is inferred.
- PS2 preview is double-sided; generated normals are preview data, not recovered source normal vectors. Split positions retain XZ offsets plus the attributes offset in sourceBindings.packetChunks, rather than claiming a contiguous XYZ buffer.

### Explicit subinstance assembly

First-pass geometry-only exports mixed local cell coordinates with world transforms and omitted repeated prop placements. This was found during headless GLB QA and corrected before deployment. Type29 at+108 gives subinstance count. A nonempty list has an additional16-byte extension after its208-byte prefix, then96-byte records at+224. Each record contains matrix0..63, source-local bounds64..87, mesh index88 and flags92. The full resource must be224+count*96 bytes; each index, affine matrix and duplicate mesh bounds is validated. World placement is owning node world * record local matrix. No cell-name-based matrix inference is used. Flags1,0x10001 and0x20001 retain identical record layout; their renderer/shader meanings remain uninterpreted metadata. Type67 is another affine hierarchy node, not a mesh link.

Packet/node/subinstance identity distinguishes every repeated mesh instance in the preview registry. This recovers292 render results/59,071 faces for UCP000 and1,686 results/34,043 faces for tokyo000. Other validated exports: tokyo0481,179 results/38,312 faces; suia000243/31,074; USD000590/36,251. Five GLBs preserve every loaded scene face. Generated normals and two-sided preview support unlit PS2 source geometry without asserting original-game shader reproduction.
