# Blur texture coordinate origin

Updated: 2026-11-17. 12 checks passed; development EXE updated.

The application stores image row zero at the top and samples MeshData with row 1-V. Blur PC D3D source UV0 addresses the image from the top. Forwarding raw UV0 therefore mirrored images vertically. The Blur decoders now perform V=1-sourceV once, keeping U and decoded texture rows unchanged. Out-of-range repeated coordinates are preserved, not clamped.

Original shaders-speed.pak version 1 directory contains 1,256 entries. Nine Default, SpeedTree and billboard FXB resources were decompressed to exact declared sizes for static inspection. Default_LN_NB_NV uses mov o1.xy,v2 and its base sampler samples interpolated XY directly. SpeedTree similarly retains XY; SpeedTreeLeaf_LN multiplies XY by unit constants. No automatic vertical inversion is present in those primary texture paths. The parsed Haruna instance g_vUVOffset values are zero. This does not implement all game shaders or validate every shader permutation.

Implementation: src/blur_model.h shared meshUv adapter and standalone reader; src/blur_scene_geometry.inc paired scene reader. Material provenance records sourceUvTopLeft and uvVFlipped. Tests cover asymmetric corners with the viewer sampling convention and compare decoded real scene UVs against original source half pairs. Positions, triangulation, source offsets and image pixels are unchanged.

Private evidence: Codex workspace blur-research/probe_shaders.py, shader-pak-index.json, shader-sample-*.bin/.asm, disassemble-shaders.py. Do not commit game binaries or shader dumps. No commit/push/release or interactive launch requested/performed.
